# Lessons

- 2026-03-10: When a user says a live transcript is hard to read, do not stop at font tweaks. Guarantee the transcript panel enough layout space with an explicit minimum footprint, especially when it shares a column with controls and forms.
- 2026-03-10: When a user says a strategic dashboard is showing “seeded” metrics, audit the component for local arrays/constants first and rewire it to existing live endpoints before polishing layout or labels.
- 2026-03-10: When the voice console fails on click, inspect backend logs for config errors and static asset 404s before treating it as a pure UI bug. Missing voice API keys and broken worklet paths can present as “the call button does nothing.”
- 2026-03-10: If a user references `agents.mmd` but the repo uses `AGENTS.md`, verify the actual root instruction file first and then restart the project workflow from that file instead of assuming the name mismatch is harmless.
- 2026-03-09: When splitting two dashboards, do not stop at separate routes. Remove repeated sections and repeated metrics so each dashboard has a distinct job-to-be-done.
- 2026-03-09: When a user says two dashboards should stay separate, keep their information architecture separate in the product too. Do not assume a combined page is acceptable just because the metrics are related.
- 2026-03-09: When a user says similar product surfaces should stay separate, do not keep them on a combined raw board. Split them into distinct handoff pages instead of assuming adjacency is acceptable.
- 2026-03-09: When a user asks for designs only, remove all narrative chrome by default. Do not add labels, captions, decorative cards, or other wrapper UI around the product surfaces unless they explicitly ask for presentation framing.
- 2026-03-09: When delivering Figma animation assets, do not stop at “the frames exist in the file.” Verify they are obvious to discover as standalone frames or a filmstrip; a technically correct but buried long canvas still fails the handoff.
- 2026-03-09: When a repo has a root `AGENTS.md`, read it and switch to that workflow before doing any substantial work. Do not rely on default habits when the project defines its own planning, task-tracking, and verification loop.
- 2026-03-09: When delivering captured media assets, do not trust the filename or the earlier run summary. Open the actual exported image files and verify the pixels before handing them off, especially after any server restarts or browser-focus workarounds.
- 2026-03-09: When shipping a new flagship surface, “working” is not enough. The first pass must meet production-marketing quality for hierarchy, layout, and action presentation, especially on customer-facing AI control panels.
- 2026-03-09: When writing a shareable product or pitch document for a role-based platform, include a basic user flow for each supported login persona by default; otherwise the team still lacks the practical operating picture.
- 2026-03-09: When the user asks for a team-shareable document, confirm or infer the required output format early. If they want something easy to circulate, produce the final artifact in that format directly instead of stopping at markdown.
- 2026-03-07: Voice identity confirmation must normalize Unicode punctuation and recover from fragmented STT finals before workflow progression, otherwise mixed-script names can be dropped and the call can loop or stall.
- 2026-03-07: Voice workflow turns must distinguish "please tell me your name" from "am I speaking with X", and awareness denials like "I didn't know" must trigger an explain-first overdue prompt instead of jumping straight to payment pressure or looping callback requests.
- 2026-03-07: Voice fixes must cover both deterministic prompts and interrupted dynamic LLM turns. If the parser, name acknowledgement, or Hindi voice-gender logic only exists in fixed prompts, barge-ins will bypass it and reintroduce the bug.
- 2026-03-08: Post-identity meta questions like "did you hear my name?" must not be consumed as awareness or payment answers; they need an explicit name-confirmation response and the original workflow step must stay pending.
- 2026-03-08: Once the call reaches `closing`, meaningful payment objections or updated commitments must be rebound to the last payment-resolution step, while abusive language should get a dedicated safe-exit response instead of the generic farewell loop.
- 2026-03-10: When building a voice-agent QA pack, do not stop at happy-path and standard operational branches. Include adversarial Hindi scenarios by default: profanity, manipulation, AI-awareness, prompt-injection, contradiction, token-wasting, legal threats, privacy probes, and off-workflow derailment attempts.
- 2026-03-10: Date commitments like `payment on 12th` must be treated as real PTP candidates in the live workflow, not just full dates or relative phrases. If ordinal day-of-month parsing is missing, the agent will loop its question and lose trust immediately.
- 2026-03-10: When a user reports a broken live conversation, do not treat each utterance in isolation. Verify language adaptation, user-question priority, payment-status branching, explicit PTP confirmation, and repetition control together because failures in those modules compound into the same call loop.
- 2026-03-10: When wiring Azure OpenAI, do not infer that the repo's currently configured deployment is the right one for a new product surface. If the user names a specific deployment such as `gpt-5.2-chat`, wire that deployment explicitly for the feature instead of reusing a different global deployment by assumption.
- 2026-03-10: When a user explicitly says to follow `AGENTS.md` strictly, restart the project workflow from the root instructions: re-read task tracking files, write a fresh plan into `tasks/todo.md`, check in before implementation, and produce the requested validation artifacts instead of assuming the previous turn's structure is sufficient.
- 2026-03-10: If a user adds or fixes `.env` while the app is already running, verify whether critical integrations are held inside long-lived singletons. Reload or refresh that runtime config in the code path, or explicitly account for restart requirements; otherwise “the key is present now” still leaves telephony broken.
- 2026-03-10: When users report the UI “switching dark/light” during ordinary interactions, do not assume the global theme toggle is firing. Inspect shared component states like loading, disabled, light/subtle variants, and any `auto` color-scheme storage first; fallback library styles can masquerade as a full theme flip.
- 2026-03-10: Dark-mode work is not complete when the theme toggles and the primary layout looks correct. Verify screenshot-level contrast on live metrics, table cells, chart axes, empty states, and nav borders; library defaults often stay too dark against black surfaces.
- 2026-03-10: Do not mix CSS-variable dark mode with unverified `theme.colorScheme` conditionals in shared component theme overrides. If the shell uses CSS variables, the Mantine card/paper/table/input surfaces should also read from CSS variables or the UI will split into dark chrome with light content panels.
- 2026-03-10: When a user says a button-fit fix is still incomplete, rerun the live audit at narrower desktop widths before declaring the surface clean. Wide-only screenshot checks can miss rail/grid truncation that appears around 1200-1366px.
- 2026-03-10: When a dashboard exposes scope filters like task state or DPD bucket, verify every backing query honors them. If only the bottom table is filtered while headline metrics stay campaign-wide, the page is not fully wired.
